## Шлях автомата

До бару 4 130 (BTC) / 4 250 (ETH) обидві політики йдуть **тим самим** шляхом (однакові рішення, крива й переходи).
Усі три COOLDOWN-и кожного символу настають через денний ліміт (`PnL_day ≤ −2 %`); до кінця тієї самої UTC-доби
нові входи й так відхиляє `max_daily_loss`. Перші два закінчуються о північ UTC (денний PnL скинуто, DD ≤ 0.05,
витримка минула); третій — при DD 0.0599 / 0.0600 > `cool_exit` = 0.05, тож за `reduce_only` вихід неможливий
(ENG-14), а за `scaled_entries` стратегія торгує далі з κ_mode = 0.25. Тут політики й розходяться.

## Висновок (чесно)

1. **`scaled_entries` усуває поглинання, але не рятує стратегію.** Після третього COOLDOWN стратегія торгує далі з
   κ_mode = 0.25 (190 / 221 входів), тож капітал і DD змінюються — стан уже не поглинаючий за побудовою. Але на цьому
   вікні в угод, відкритих у COOLDOWN, валового результату майже немає (+0.38 / −24.77 USDT), а комісії —
   601.28 / 572.72 USDT; DD росте з 0.06 до 0.12 за 7 596 барів (BTC, 5.3 доби) / 7 075 барів (ETH, 4.9 доби) і
   спрацьовує засувка HALTED. У бектесті її ніхто не знімає (зняття — лише admin), тож 81.9 % / 82.5 % вікна —
   HALTED. Це робота контуру за задумом: жорстка межа 12 % обмежила збиток, як і має.
2. **`reduce_only` програє вдвічі менше лише тому, що перестає торгувати** (−5.99 % проти −12.00 % на BTC):
   це не перевага політики, а наслідок поглинання — у 94.9 % / 93.9 % вікна стратегія стоїть.
3. **Корінь — не автомат, а очікування стратегії після витрат:** валовий PnL за 45 днів ≈ 0 (BTC +63.32, ETH −25.57
   USDT) при комісіях 1 169–1 263 USDT. Це питання для walk-forward / сітки (вибір `u_enter`, `χ`, `ρ`), а не для
   ризик-контуру; на вибір політики COOLDOWN ці числа впливають лише так: за `scaled_entries` стратегія без переваги
   доходить до HALTED, за `reduce_only` — зависає в COOLDOWN.

## VaR₉₅/CVaR₉₅ точок кривої на тих самих прогонах (RF-03)

У всіх чотирьох прогонах: визначені в 64 300 з 64 800 точок (перша — індекс 500, тобто після 500 дохідностей),
`CVaR ≥ VaR` — у 64 300 з 64 300, `VaR ≥ 0` — у 64 300 з 64 300 (на цих кривих; у загальному випадку VaR ≥ 0 не
гарантовано, R-04); медіана VaR₉₅ — 0.0000 USDT (більшість вікон — пласка книга: HALTED/COOLDOWN), максимум
3.6706 USDT (BTC) / 3.9229 USDT (ETH) — однаковий для обох політик, бо припадає на спільну частину шляху. Один
векторизований прохід `risk.var.var_cvar_money` над 64 800 точками — 0.098–0.105 с (та сама команда).

## Перевірка рецензентом (2026-09-19)

Ті самі чотири команди повторено послідовно після рецензії (у `--report` додано два рядки: «max per-bar DD increase
by state of the previous bar» і «entries/flips with sizing traces …» — з них три рядки таблиці, позначені
«рецензія»). Усі інші числа таблиці, шлях автомата й VaR-зведення **збіглися** до останнього знака, включно з
`equity_hash` усіх чотирьох прогонів. Час повного прогону `--report` на цьому повторі — 4.06 / 4.58 / 4.05 / 4.77 с
(порядок колонок таблиці), прохід `var_cvar_money` над 64 800 точками — 0.095–0.106 с.

* **κ на реальних даних.** Кожен із 303 / 113 / 358 / 137 входів і розворотів отримав у сайзері κ = κ_mode стану, в
  якому його рішено, і схвалена ціль не перевищує `floor(κ_mode·min(q_atr, q_vt, q_lev))`, тобто κ_mode-частки
  розміру NORMAL для тих самих входів; 190 / 221 із них — у COOLDOWN з κ = 0.25. Відтак `scaled_entries` не дає
  жодного шляху до експозиції понад κ-масштабований розмір.
* **Швидкість просадки проти оцінки §5.12.** Найбільший приріст DD за один бар у кожному стані нижчий за
  κ_mode·ρ_base (з κ_slip = 0): у COOLDOWN за `scaled_entries` — 0.00064 / 0.00056 проти 0.00125. Це спостереження
  на цих даних, а не доведення: межа не враховує гепів, відкату нереалізованого прибутку і комісій
  (`risk/margin.py`, RF-04).
* **`config_hash` змінився для всіх прогонів.** `reduce_only` (`61cbcda3…`) відтворює криву першого прогону
  (`equity_hash 8a82f814…`), але його `config_hash` ≠ `7f91fc34…` з `first_run_metrics.md`: різниця — лише явне поле
  `cooldown_policy` (без нього ідентичність дає рівно `7f91fc34…`, RF-01).
