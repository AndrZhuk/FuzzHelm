# Керівництво користувача FuzzHelm

Автор: Андрій Жук, 2026. Як підняти стенд — `docs/manuals/deployment.md`.

## 1. Демонстрація без мережі: реплей записаної сесії

```bash
uv run python -m fuzzhelm.workers.trading_worker --profile replay --speed inf --no-db   # без бази, лише підсумок
uv run python -m fuzzhelm.workers.trading_worker --profile replay                       # з базою і веб-панеллю
```

Воркер відтворює записану 45-хвилинну сесію Binance (`fixtures/ws/btcusdt_2026-09-18.jsonl.gz`) через той самий
конвеєр збору даних і той самий торговий цикл, що й бектест. На кожній закритій свічці він ухвалює рішення, записує
його з повним поясненням і надсилає подію в панель. У шапці екрана «Онлайн» видно режим роботи:
`MODE: PAPER · FEED: REPLAY · NO MAINNET KEYS`.

## 2. Демонстрація ризик-контуру: обвал ціни → HALTED

```bash
uv run python scripts/demo_flash_crash.py
```

Сценарій: поки стратегія тримає довгу позицію, ціна різко падає на 6,5 %. Стоп закриває позицію, денний збиток
перевищує ліміт 3 %, і система **сама** переходить у режим HALTED: далі жодного ордера. Зняти зупинку може лише
адміністратор, вказавши причину. Причина і стан «до/після» потрапляють у журнал аудиту.

## 3. Бектест

```bash
make backtest SYMBOL=BTCUSDT          # або ETHUSDT
```

Скрипт бере 45 днів свічок з бази, проганяє торговий цикл, записує прогін з паспортом відтворюваності і будує
`docs/figures/metrics_<SYMBOL>.md` та `docs/figures/equity_<SYMBOL>.png`. Той самий вхід і seed дають побайтово
той самий результат (`equity_hash`). Бектест також можна запустити з панелі.

## 4. Веб-панель

`make ui` → `http://localhost:5173`. Вхід — логін і пароль користувача API (команда `fuzzhelm user add`).
Ролі: **analyst** (лише перегляд), **operator** (правила і стратегії), **auditor** (журнал аудиту),
**admin** (ліміти ризику і зняття аварійної зупинки).

1. **Виведення** (`/explain/{id}`) — як ухвалено одне рішення, у семи кроках: входи T, R, V і функції належності →
   спрацьовані правила → агрегована фігура і центроїд → коефіцієнт довіри κ → розмір позиції → перевірки ризику →
   пояснення українською.
2. **Онлайн** (`/live`) — свічки, шість детекторів, вихід нечіткого ядра, режим ризику, відхилені ордери, стан
   потоку даних. Потрібен запущений воркер реплею (розділ 1).
3. **Бектест** (`/backtest`) — список прогонів і запуск нового, крива капіталу з просадкою, паспорт прогону, метрики,
   редактор правил (кожне збереження створює нову версію стратегії).

## 5. Живі дані

```bash
uv run python -m fuzzhelm.workers.ingest_worker --minutes 30              # лише збір даних у базу
uv run python -m fuzzhelm.workers.trading_worker --profile paper --minutes 30   # паперова торгівля на живих даних
```

Потрібна мережа. Використовуються лише публічні дані Binance; ордери виконує симулятор.

## 6. Якщо щось не працює

* «Немає зв'язку з API» — не запущено `uvicorn`.
* «Даних ще немає» на екрані «Онлайн» — не запущено воркер реплею.
* «Прогонів ще немає» — виконайте `make backtest`.
* Помилка підключення до бази — `docker compose up -d db` і `uv run alembic upgrade head`.
