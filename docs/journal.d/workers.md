## 2026-09-19 — workers: торговий і ingest-воркери, запис прогонів, перший повний прогін, демо flash_crash (фази 6, 8, 9)

написано з нуля поверх готових рушія, API і сховища. Архітектурне рішення — рушій лишається чистим, а воркери є межею:
`workers.persist` відображає записи рушія (StepResult/BacktestResult уже мають форму рядків DDL §6) у репозиторії storage
— пакетно для готового прогону (executemany частинами, капітал — COPY) і покроково для live (кожен бар — одна транзакція
разом із NOTIFY для SSE). `workers.trading_worker` — один `TradingSession`: прогрів ознак рівно 523 барами історії строго
до першої свічки потоку (з БД, а якщо в БД дірка — із записаних рядків REST для replay чи з публічного REST для paper, з
записом у `candle`), далі кадри → `IngestPipeline` → закриті свічки → `TradingLoop.on_candle` (той самий `step()`, що й у
бектесті) → запис і події `candle/decision/fill/rejection/risk/equity/health`. Паспорт live-прогону містить config_hash
профілю, git_sha з прапорцем `git_dirty`, seed, рушій, а `dataset_hash` — ідентичність сесії (джерело, sha256 файлу,
прогрів, момент старту), бо дві сесії з тими самими даними — різні події; журнал прогону — хеш-ланцюг від `session.start`
через кожну спожиту свічку, заявки, виконання, рішення, кожен `risk_event` і команди керування до `session.end`.
Команди API (зняття kill-switch, зміна лімітів) воркер бере з `audit_log` (LISTEN лише будить), роль актора перечитує з
`app_user` і застосовує між барами; для цього в рушії виправлено дрібний дефект — перехід HALTED → COOLDOWN, спричинений
адміністратором між барами, раніше губився з записів кроку. Шапка «MODE: PAPER · FEED: REPLAY · NO MAINNET KEYS · SEED ·
Q» іде подією `health` у GET /market/health.
