## Докази за пунктами

### 1. Репозиторій поза iCloud; `docker compose up` — 4 сервіси з нуля (частково)
- **Виконано:** робоча копія лежить у `/Users/andriizhuk/dev/fuzzhelm`, не в iCloud Drive (брифінг §0.3).
- **Виконано (фаза 9):** `docker compose config --services` → `db`, `api`, `ui`, `worker` — **чотири сервіси**. З `ui` знято
  профіль, каталог `./ui` існує, сервіс отримав `FUZZHELM_API=http://api:8000` (Vite проксіює `/api`, CORS не потрібен),
  іменований том `ui_node_modules` і `depends_on: [api]`. Воркеру додано `./data:/app/data:ro`, інакше він не бачить
  `data/anomaly_mlp_*.json` (`data/` у `.dockerignore`) — це був окремий дефект попередньої редакції (UI-07).
- **Не виконано «з нуля однією командою»:** на порожньому volume після `up` ще потрібні `uv run alembic upgrade head` і
  `uv run fuzzhelm backfill --days 45` (README, «Швидкий старт»): `docker compose up` міграцій не запускає, бо `api` стартує
  лише `uvicorn`. Підйом усіх чотирьох сервісів з порожнього тому в цій сесії **не перевірявся** — робоча БД працює і її не
  зупиняли; перевірено лише те, що compose-файл оголошує чотири сервіси і що `ui` збирається (`npm run build`).
- **Що потрібно:** рішення провідного розробника — додати крок міграцій у старт `api` або окремий сервіс ініціалізації;
  після цього студент **[ЛЮДИНА]** один раз проганяє `docker compose down -v && docker compose up`.

  шукав значення `BINANCE_TESTNET_KEY/SECRET`, `TELEGRAM_BOT_TOKEN`, `FUZZHELM_JWT_SECRET` довжиною ≥ 8 символів. Знайшов лише
