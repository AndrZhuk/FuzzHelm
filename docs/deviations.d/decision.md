## DEC-01. «Узгодженість = 1, якщо всі детектори одного знаку» — неточне твердження
- **Що в спеці:** тест §10 H має назву `test_agreement_is_one_when_all_same_sign`. Отже, припускається, що коли
  всі детектори мають однаковий знак, то `A_g = 1`.
- **Що насправді:** за формулою брифінгу (§5.4) `p₀ = Σ ω c (1 − |s|) / Z`, тобто незадіяна сила детектора
  потрапляє в окрему категорію. Якщо всі `s_k` мають однаковий знак, але хоча б один `|s_k| < 1`, то `p₀ > 0`
  і `H > 0`, а отже `A_g < 1`. Приклад: при `s ≡ 0.5` маємо `p = (½, 0, ½)`, `H = log₃2 ≈ 0.631`,
  `A_g ≈ 0.369`, `κ ≈ 0.590`. Точне твердження таке: однаковий знак дає `p₋ = 0` (або `p₊ = 0`), звідки
  `H ≤ log₃2`, `A_g ≥ 1 − log₃2 ≈ 0.3691` і `κ ≥ 0.35 + 0.65·0.3691 ≈ 0.590`.
  `A_g = 1` виходить лише тоді, коли всі детектори з ненульовою вагою мають однаковий знак і `|s| = 1`
  (або всі `s = 0`). Саме цю межу брифінг і наводить: «`p = (1,0,0)` ⇒ `κ = 1.0`».
- **Що зробив:** назву тесту залишив дослівно. Тест перевіряє однаковий знак при `|s| = 1` (`A_g = 1`, `κ = 1`
  точно, для лонгу й шорту, причому VolRegime присутній, але не голосує). Додав модульний тест
  `test_agreement_same_sign_partial_strength_is_bounded_below` з точним значенням `H = ln2/ln3` при `s ≡ 0.5`
  і property-тест `test_same_sign_agreement_is_bounded_by_log3_2`.
- **Чим обґрунтовано:** це наслідок власної формули брифінгу з трьома категоріями. Тест на рівність 1 для
  будь-яких однознакових `s` падав би, а послабити його до «≈ 1» було б нечесно. Для звіту це означає, що
  навіть одностайні, але помірні за силою детектори отримують гасіння `κ < 1`. Це узгоджено з задумом:
  `p₀` — «незадіяна маса свідчень».

## DEC-02. Узгодженість при нульовій / мізерній масі свідчень (Z < ε)
- **Що в спеці:** `p_i = Σ … / Z`. Випадок `Z = 0` не визначено (усі `c = 0` під час прогріву, або
  голосують лише CONTEXT-детектори).
- **Що насправді:** при `Z = 0` формула дає 0/0. При субнормальних `Z` (hypothesis їх генерує) чисельники
  частково зникають через underflow, і тотожність `p₊+p₋+p₀ = 1` порушується.
- **Що зробив:** `p_i = (Σ ω c m_i + (ε − Z)⁺/3) / max(ε, Z)` з тим самим `ε = 1e−9`, що й у консенсусі.
  Бракуючу до ε масу розподілено рівномірно, тобто за апріорним розподілом максимальної ентропії.
  При `Z ≥ ε` формула брифінгу працює без змін. При `Z = 0` маємо `p = (⅓,⅓,⅓)`, `H = 1`, `κ = κ_min`,
  а на межі `Z = ε` вираз неперервний. `Agreement.has_evidence` і текст `narrate` явно повідомляють
  про такий стан. Тести: `test_entropy_handles_zero_probability`,
  `test_agreement_small_mass_regularization_is_continuous_at_eps`, `test_agreement_without_any_voting_detector_gives_kmin`.
- **Чим обґрунтовано:** «немає свідчень — максимальне гасіння» — найобережніший варіант для ризик-контуру.
  Він симетричний до `max(ε, ·)` у знаменнику консенсусу і зберігає тотожність суми ймовірностей
  на всьому просторі входів.

## DEC-03. V до прогріву VolRegime
- **Що в спеці:** `V_t` — це вихід VolRegime (перцентильний ранг σ_P). Поведінку до прогріву
  (`L = 500` барів) не описано.
- **Що насправді:** справжній `detectors/vol_regime.py` до прогріву повертає не NaN, а заглушку
  `c = 0, features = {"V": 0.5, "warm": 0.0}`. Перша версія агрегатора перевіряла лише скінченність `V`,
  тому на реальних даних (522 перші бари з 2000 у `fixtures/golden/source_klines_btcusdt_1m.json`)
  трасування позначало `v_source = "vol_regime"`, тобто видавало заглушку за вимір, а `narrate`
  мовчало про прогрів. Числове значення V від цього не змінювалося (обидва 0.5). Знайдено й виправлено
  під час незалежного рев'ю.
- **Що зробив:** якщо CONTEXT-виходу з `features["V"]` немає, його `c = 0` (прогрів за контрактом
  `detectors/base.py`), або `V` дорівнює `None` чи не скінченне, `consensus` бере `V = 0.5` (параметр
  `v_default`) і позначає `Consensus.v_source = "default"`. `narrate` про це прямо повідомляє.
  Два CONTEXT-виходи з ключем `V` (навіть якщо один ще прогрівається) і виміряне `V ∉ [0, 1]` дають
  `ValueError`. Тести: `test_consensus_context_warmup_with_zero_confidence_uses_default`
  і `test_decision_core_end_to_end_with_real_detectors_and_mamdani` (справжні детектори й Мамдані:
  `v_source = "default"` рівно тоді, коли `c` VolRegime дорівнює 0).
- **Чим обґрунтовано:** 0.5 — математичне сподівання перцентильного рангу, коли інформації немає.
  До прогріву трендові й реверсійні детектори мають `c = 0`, тому `T = R = 0` і `κ = κ_min`,
  а отже, вибір V на рішення практично не впливає. Альтернатива (виняток) зламала б бектест
  на перших барах.

## DEC-04. Запит до фундаменту (необов'язковий)
- `DetectorOutput.__post_init__` перевіряє межі `s` і `c`, але не `weight`. Від'ємна або нескінченна `ω`
  зламала б опуклість консенсусу, тому зараз `consensus`/`agreement` перевіряють її самі й кидають
  `ValueError`. Варто додати таку ж перевірку `0 ≤ weight < ∞` у `detectors/base.py`. Фундамент я не
  редагував.
