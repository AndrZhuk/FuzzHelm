# Розходження «спека ↔ реальність»: features / detectors / regimes

Формат: **що в спеці / що насправді / що зробив / чим обґрунтовано**.

## F-01. Пін-бар «нуль при симетричних тінях»
- **Спека:** тест `test_pin_bar_score_zero_when_wicks_symmetric`; формула §5.2
  `π = σ_s(W_l/max(B,ε) − 2)·σ_s(1 − W_u/max(B,ε))·min(1, Rg/ATR)`.
- **Насправді:** при W_l = W_u = W (r = W/B) формула дає σ_s(r − 2)·σ_s(1 − r). Аргументи в сумі дають −1,
  тож добуток максимальний при r = 1.5 і дорівнює σ_s(−0.5)² ≈ 0.0333, **не нуль** (перевірено тестом:
  межа досягається з відносною точністю 1e−12).
- **Зроблено:** формулу брифінгу не змінено. Тест перевіряє те, що справді нульове: π⁺ == π⁻ побітово,
  тож чистий знаковий пін-скор π⁺ − π⁻ = 0 і сила детектора s = 0.0 точно; додатково перевіряється межа
  π ≤ σ_s(−0.5)² і контроль (класичний молот дає π⁺ > 0.9).
- **Обґрунтування:** «підганяти» формулу під назву тесту (напр. віднімати поріг) означало б вводити
  поріг, якого у формулі немає; у консенсус іде s, і вона рівно нульова.

## F-02. Donchian: означення U_t і «пробою»
- **Спека:** `s = tanh(d_t/0.5)`, `d_t = (p_t − U_t)/ATR_t`, `c = min(1,(U−L)/(6ATR))·exp(−0.3·bars_since_breakout)`;
  що таке U_t і «пробій», не сказано.
- **Насправді:** якщо U_t включає поточний бар, то p_t ≤ h_t ≤ U_t, тож s ≤ 0 завжди (детектор тренду
  ніколи не дав би сигналу вгору). Якщо U_t — канал попередніх барів, то всередині каналу d ≈ −(кілька ATR)
  і s ≈ −1 майже весь час.
- **Зроблено:** U_t, L_t — канал **попередніх** n = 20 барів; пробій — подія «закриття поза цим каналом»
  (канонічне правило Дончіана/«черепах»); у формулі d роль U відіграє **пробитий рівень** U* (U при пробої
  вгору, L при пробої вниз — дзеркально для ведмежого боку); до першого пробою s = c = 0.
- **Обґрунтування:** це єдине прочитання, у якому має сенс множник `exp(−0.3·bars_since_breakout)`: сигнал
  живе після пробою, а довіра згасає з віком. Закриття рівно на пробитому рівні дає d = 0, тож перший пробій стартує з s ≈ 0 без стрибка (але якщо
  був давніший пробій, новий пробій переносить U* і внесок c·s змінюється стрибком — неперервність за ціною
  НЕ гарантується в загальному випадку);
  подія пробою — визначення події (як сам лічильник барів), а не поріг на скор.
- **Спостереження (тест):** на барі пробою ширина каналу ще «до пробою»; на наступному барі сам пробійний
  бар розширює канал, тому c між віком 0 і 1 може зрости. Строге згасання перевіряється при сталій ширині
  (точно `exp(−0.3·k)`) і в наскрізному сценарії з віку 1.

## F-03. RsiExhaustion: `div_score` не визначено
- **Спека:** `c = min(1, 0.6·|z|^0.8 + 0.4·div_score)`, без означення div_score.
- **Зроблено:** неперервна міра дивергенції без `if`: `a = tanh(Δc_k/(ATR·√k))`, `b = tanh(ΔRSI_k/10)`,
  `ζ = tanh(z/0.1)`, `div_score = max(0, −ζ·a)·max(0, ζ·b) ∈ [0,1]`, k = 14.
- **Обґрунтування:** бичача дивергенція (ціна ↓, RSI ↑) підсилює довіру до сигналу перепроданості (z > 0),
  ведмежа — перекупленості; протилежна дивергенція довіри не додає. √k — дифузійний масштаб руху ціни за k барів,
  10 пунктів RSI — помітна зміна осцилятора. Параметри k, 10, 0.1 — експертні; за потреби виносяться в YAML.

## F-04. CandleGeometry: набір патернів j, голоси v_j, dist_to_level
- **Спека:** `s = clip(Σ sign_j·v_j·score_j / Σ v_j, −1, 1)`, `c = max_j score_j·exp(−dist_to_level/(2ATR))`;
  формула дана лише для бичачого пін-бару; v_j і dist_to_level не визначено.
- **Зроблено:** j ∈ {pin_bull (формула брифінгу), pin_bear (дзеркало), engulf_bull, engulf_bear}; поглинання —
  добуток гладких σ_s (розмір тіла відносно попереднього, колір поточного і попереднього бару, min(1, Rg/ATR)).
  Голос v_j = w_j·score_j (апріорна вага × присутність). dist — для кожного патерну до «свого» рівня каналу
  Дончіана: бичачі — |low − L|, ведмежі — |high − U|; c = max_j score_j·exp(−dist_j/(2ATR)).
- **Обґрунтування:** при сталих v_j s ділилася б на Σ всіх голосів і сигнал одного чистого патерну стискався б
  до 1/4; з v_j = w_j·score_j |s| = score, коли спрацював один патерн. Покомпонентна відстань — природне
  уточнення формули брифінгу (збігається з нею, коли домінує один патерн): молот біля опору не є підтвердженням.
  Спрощення: розташування тіл при поглинанні не перевіряється окремо (на безперервному ринку o_t ≈ c_{t−1}).

## F-05. Ініціалізація Уайлдера/EMA і пласкі ряди
- **Спека:** рекурентні формули без стартового значення.
- **Зроблено:** EMA, ATR, RSI ініціалізуються середнім перших n значень (конвенція TA-Lib); ATR/RSI — перше
  значення на барі з індексом n. RSI при Ḡ = L̄ = 0 → 50 (TA-Lib повертає 0, що означало б «перепроданість»
  на пласкому ринку). Ця сама конвенція — у незалежному `scripts/make_golden.py`.

## F-06. Golden-дані: незалежна реалізація + один зовнішній опублікований приклад
- **Спека:** golden CSV для RSI14/ATR14 (+ за можливості зовнішній опублікований приклад).
- **Насправді:** TA-Lib/pandas у залежностях немає (ставити заборонено). Первинна версія модуля не включила
  приклад StockCharts ChartSchool, бо перерахунок за цінами, округленими до 0.01, дає 70.46, 66.25, … проти
  опублікованих 70.53, 66.32, … Рецензія показала, що причина не в джерелі, а у вхідних даних: таблиця
  StockCharts (cs-rsi.xls) містить ціни з **4 знаками** (44.3389, 44.0902, …); з ними всі 19 опублікованих
  значень RSI(14) відтворюються до 0.01 (перевірено тестом). Такий збіг 19 з 19 з хибними цінами неможливий,
  тож приклад вважаємо відтвореним достовірно (джерело — пам'ять, перевірка — самоузгодженість).
- **Зроблено:** (1) реальні 2000 свічок Binance (фіксоване вікно) + незалежна пакетна реалізація у
  `scripts/make_golden.py` (інші цикли, форма `(prev·(n−1)+x)/n`, RSI як `100 − 100/(1+RS)`); інкрементальні
  класи збігаються з нею до 1e−9; (2) `test_wilder_golden_csv_matches_exact_rational_recurrence` — golden-CSV
  проти точної раціональної арифметики (`Fraction`) тих самих означень, розбіжність ~4e−12 (межа тесту 1e−10);
  (3) `test_rsi14_matches_stockcharts_published_example` — зовнішній приклад, допуск 0.005 (округлення публікації);
  EMA-згладжування α = 2/(n+1) цей приклад не відтворює (розбіжність > 1 пункту RSI). Окремо тест показує, що
  α = 2/(n+1) дає розбіжність з golden ATR > 1 USDT.
- **Обґрунтування:** golden звіряє два різні float-шляхи одного означення плюс точну арифметику; зовнішній
  приклад незалежно підтверджує саму конвенцію (ініціалізація середнім перших 14 змін, α = 1/n). Зовнішнього
  еталона для ATR у модулі немає — це чесно зазначаємо у звіті.

## F-07. Велфорд на ряді зі зсувом 1e9: точність ~1e−6, не машинна
- **Спека:** «наївна Σx² тут падає» (Велфорд — стабільний).
- **Насправді (виміряно):** наївна формула — похибка > 100 % і від'ємні «дисперсії»; ковзний Велфорд (add/remove) —
  максимальна відносна похибка 1.03·10⁻⁶ на 5000 барах: округлення середнього на рівні 1e9 (ulp/2 ≈ 6·10⁻⁸)
  відносно σ ≈ 4.6 накопичується між ресинхронізаціями.
- **Зроблено:** поріг тесту 1e−5 з поясненням; додано періодичну точну ресинхронізацію ковзних сум
  (раз на 1024 оновлення, амортизовано O(1)), якої в брифінгу немає; тест на 100 000 барів показує, що дрейф обмежений.

## F-08. «O(1) на бар» для перцентильного рангу
- **Спека:** §5.1 «Індикатори (O(1) на бар)», включно з V_t за L = 500.
- **Насправді:** відсортований список + bisect: пошук O(log L), вставка/видалення — зсув масиву O(L)
  (memmove, для L = 500 — кілобайти). Разом конвеєр — 4.36 мкс/бар (виміряно).
- **Зроблено:** у коді й API складність указано чесно (O(L) з малою константою).

## F-09. Bandwidth = 2σ/μ
- **Спека:** `bw = 2σ/μ`. Класичний BandWidth Боллінджера = (upper − lower)/middle = 4σ/μ при k = 2.
- **Зроблено:** буквально 2σ/μ; для довіри BollingerZ використовується лише перцентильний ранг bw, інваріантний
  до сталого множника, тож на c це не впливає. σ — популяційне (ddof = 0), як у Боллінджера.

## F-12. KMeans: стандартизація і силует на підвибірці
- **Спека:** KMeans(k=3) на (перцентиль σ_P, нормований нахил EMA, z-score обсягу), k за силуетом.
- **Зроблено:** колонки стандартизуються перед KMeans (різні масштаби), центроїди повертаються в оригінальних
  одиницях (центроїд = середнє кластера, афінна інваріантність); `n_init = 10` явно, `random_state = seed`.
  Силует при n > 10 000 — на детермінованій підвибірці 10 000 (повний силует O(n²)).
  Якщо силует обирає k ≠ 3, це повертається як `k_best` + попередження; V все одно з k = 3.
- **Вікно z-score обсягу** (60 барів) у брифінгу не задано — обрано годину 1m-барів; ключ `features.volume_window`.

## F-15. Перцентильний ранг із нічиїми: повністю пласке вікно дає V = 1
- **Спека:** `V_t = (1/L)·Σ 1[σ_{P,i} ≤ σ_{P,t}]` (нестрога нерівність).
- **Насправді:** якщо всі L = 500 значень σ_P однакові (напр. 0 під час довгої зупинки торгів — 523+ пласких
  барів), то V_t = 1, тобто режим «HI» при нульовій волатильності. Так само bb_bw_rank = 1 на пласкому вікні
  (для BollingerZ це безпечно: c = 1 − ρ = 0). Одиничні пласкі бари серед звичайних дають низький ранг, як і слід.
- **Зроблено:** формулу брифінгу не змінено (реалізація буквальна, перевірена property-тестом проти наївного
  підрахунку). Зафіксовано як обмеження; для реальних 1m-даних BTCUSDT такий стан — ознака проблеми якості
  даних, яку має ловити `quality` (stale_data), а не детектор режиму.
