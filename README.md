# FuzzHelm

Навчальний сервіс, який збирає ринкові дані з біржі Binance, ухвалює торговельні рішення за нечіткими
правилами і автоматично обмежує ризик. Торгівля — лише **паперова** (симуляція): реальних грошей і реальних
ордерів у системі немає за побудовою.

Проєктно-технологічна практика, кафедра АСУ НУ «Львівська політехніка», 2026. Автор: Андрій Жук.

## Що вміє

| Пункт завдання | Де в коді |
|---|---|
| Збір даних через REST (історія) і WebSocket (реальний час) | `src/fuzzhelm/ingest/` |
| Нормалізація, перевірка якості та збереження котирувань у PostgreSQL | `ingest/`, `quality/`, `storage/` |
| Рішення за заданими правилами: 6 детекторів → нечітке ядро Мамдані (45 правил) | `detectors/`, `decision/`, `fuzzy/` |
| Розмір позиції і автоматичний контроль ризиків та лімітів (6 правил + автомат станів) | `sizing/`, `risk/` |
| Паперове виконання ордерів і облік капіталу | `execution/` |
| Бектестинг на історичних даних | `backtest/`, `scripts/run_backtest.py` |
| REST API і веб-панель з поясненням кожного рішення | `api/`, `ui/` |
| Модульні тести ключової логіки | `tests/` |

## Як працює

```
Binance REST + WebSocket → нормалізація і перевірка → PostgreSQL
  → індикатори → 6 детекторів (сила сигналу + довіра) → три входи: тренд T, реверсія R, волатильність V
  → нечітке ядро Мамдані → сигнал u від −1 (продавати) до +1 (купувати)
  → розмір позиції → ризик-контур: 6 лімітів + режими NORMAL / WARNING / COOLDOWN / HALTED
  → паперове виконання → облік капіталу → API і веб-панель
```

Головна ідея: нечітке ядро лише **пропонує**, а ризик-контур **вирішує** і не може збільшити позицію — лише
дозволити, зменшити або заборонити. Це перевірено тестом на тисячах випадкових ситуацій
(`test_risk_chain_never_increases_exposure`).

## Результат бектесту

Дані: 45 днів (4 серпня — 18 вересня 2026), 64 800 хвилинних свічок на символ, з урахуванням комісій і проковзування.

| Символ | Результат | Угод | Що сталося |
|---|---|---|---|
| BTCUSDT | −12,0 % | 303 | на 9-й день просадка досягла 12 % — ризик-контур зупинив торгівлю (HALTED) |
| ETHUSDT | −12,0 % | 358 | те саме на 8-й день |

Стратегія збиткова: на хвилинних свічках витрати на угоди з'їдають слабкий сигнал. Зате ризик-контур спрацював
саме так, як спроєктовано: збиток зупинився на заданій межі 12 %. Звіти прогонів — `docs/figures/metrics_*.md`.

## Запуск

Потрібні Docker, [uv](https://docs.astral.sh/uv/) і Node.js 20+.

```bash
cp .env.example .env                  # значень за замовчуванням достатньо для локального стенда
docker compose up -d db               # PostgreSQL 16 на порту 5442
uv sync --frozen                      # залежності Python
uv run alembic upgrade head           # схема бази
uv run fuzzhelm backfill --days 45    # 45 днів хвилинних свічок BTCUSDT і ETHUSDT з Binance
uv run fuzzhelm fetch-funding         # ставки фінансування за той самий період
make backtest SYMBOL=BTCUSDT          # бектест з записом у базу
```

API і веб-панель:

```bash
uv run fuzzhelm user add --login admin --role admin               # пароль вводиться з клавіатури
uv run uvicorn fuzzhelm.api.main:app --port 8000                  # API: http://127.0.0.1:8000/docs
make replay                                                       # реплей записаної сесії (дані для екрана «Онлайн»)
make ui                                                           # панель: http://localhost:5173
```

Без мережі і без бази можна прогнати записану сесію:
`uv run python -m fuzzhelm.workers.trading_worker --profile replay --speed inf --no-db`.

Усе в контейнерах: `docker compose up -d --build` (база, API, воркер реплею, панель).

## Тести

```bash
make test        # модульні, property- і архітектурні тести, без мережі (~10 с)
make test-int    # інтеграційні тести з PostgreSQL у Docker
make lint        # ruff + mypy
```

## Структура

```
src/fuzzhelm/   бекенд (Python 3.12, FastAPI, SQLAlchemy, PostgreSQL)
ui/             веб-панель (Vue 3, Pinia, ECharts)
config/         правила, функції належності, ліміти ризику — усе як дані YAML
tests/          тести
scripts/        бектест, графіки, запис і реплей сесій
docs/           діаграми, рисунки, ТЗ, інструкція користувача
```

## Застереження

Система не є інвестиційною рекомендацією і не торгує реальними коштами. Використовуються лише публічні ринкові
дані Binance; хости біржі жорстко обмежені в `fuzzhelm/config.py`. Секрети — лише у `.env`, який не потрапляє в git.
